# 네이버 커머스API 앱 발급 (스마트스토어)

내 스마트스토어의 주문·상품·정산을 코드로 다루려면 커머스API 앱이 하나 필요하다. 절차 자체는 20분이면 끝나지만,
**영수증 캡차**와 **허용 IP** 두 곳에서 반나절을 쓰기 쉽다. 이 문서는 그 두 곳을 먼저 알려 준다.

## 0. 먼저 알 것

| 헷갈리는 말 | 실제 |
|---|---|
| "계정생성" | 새 로그인 계정이 아니다. **쓰던 네이버 아이디에 API 사용 자격(개발업체 계정)을 한 번 붙이는 절차**다. 무료이고 심사가 없으며 그 자리에서 끝난다 |
| 자격 조건 | 그 스토어의 **통합 매니저**여야 한다. 판매자센터 왼쪽 위 스토어명 아래에 "통합 매니저"라고 찍힌다 |
| 앱 개수 | 스토어당 1개. 30일 동안 호출이 없으면 휴면이 된다 |
| 사업자 정보 | 폼에 자동으로 채워진다(스토어 사업자 정보와 같다). 직접 입력할 것은 계정명과 장애대응 이메일뿐이다 |

## 1. 순서

| # | 어디서 | 무엇을 | 멈추는 지점 |
|---|---|---|---|
| 1 | `sell.smartstore.naver.com` | 로그인하기 → **"네이버 아이디로 로그인" 탭을 고른 뒤 아래 "로그인" 버튼**을 한 번 더 눌러야 네이버 로그인 창(새 탭)이 열린다 | 탭만 누르고 기다리면 아무 일도 일어나지 않는다 |
| 2 | 네이버 로그인 창 | 아이디·비밀번호. 제출은 **비밀번호 칸에서 Enter** | 아래 §2 |
| 3 | 2단계 인증 | 이메일 또는 휴대전화 6자리. **같은 IP 에서는 90일간 다시 묻지 않는다** | 인증 메일이 어느 주소로 가는지 화면의 마스킹된 주소로 먼저 확인한다 |
| 4 | `apicenter.commerce.naver.com` | 처음이면 "개발업체계정 권한을 보유하지 않은 회원" 안내가 뜬다 → **계정생성** | 안내 상자는 페이지가 뜨고 몇 초 뒤에 나타난다. 버튼이 보일 때까지 기다렸다가 누른다 |
| 5 | 가입 폼 | 계정명(14자) · 장애대응 이메일 → **인증** → 영수증 캡차 → 메일로 온 6자리 → 약관 → 가입하기 | 아래 §3 |
| 6 | 내 스토어 애플리케이션 → 애플리케이션 등록 | 이름 · 설명 · **허용 IP 3개** · API 그룹 · 토큰 스펙 확인 체크 → 등록 | 아래 §4 |
| 7 | 앱 상세 | 애플리케이션 ID 와 시크릿(**보기** 를 누르면 영수증 캡차가 또 뜬다) | 값은 화면·채팅에 찍지 말고 저장소 밖의 비밀값 파일이나 환경변수로 바로 옮긴다 |

## 2. 네이버 로그인 (브라우저 자동화로 할 때)

- 네이버 계정에는 로그인 실패 잠김이 있다. **실패가 1회 나면 멈추고 비밀번호를 사람에게 확인한다.** 메모해 둔 비밀번호가 대소문자만 다른 경우가 흔하다
- 로그인 버튼은 화면 상태에 따라 좌표가 바뀌고 CSS 선택자도 잘 안 잡힌다. 값을 넣은 뒤 **비밀번호 칸에 포커스를 두고 Enter 키 이벤트**(CDP `Input.dispatchKeyEvent` keyDown·char·keyUp, `text="\r"`)를 보내는 쪽이 확실하다
- **비밀번호 칸에 브라우저가 저장해 둔 값이 남아 있을 수 있다.** 그 뒤로 새 글자가 붙으면 틀린 비밀번호가 제출된다. 입력 전에 칸마다 Ctrl+A → Delete 로 비우고, 넣은 뒤 입력값 길이가 비밀번호 길이와 같은지 **제출 전에** 확인한다. 다르면 제출하지 않는다(그래야 실패 횟수가 올라가지 않는다)
- 로그인 뒤 판매자센터는 `accounts.commerce.naver.com/login` 의 **"네이버 아이디로 간편 로그인"** 버튼을 한 번 더 눌러야 들어간다. 대시보드 대신 로그인 전 소개 화면이 보이면 `#/home/dashboard` 로 다시 연다
- 제출 직후 페이지가 넘어가면서 CDP 응답이 타임아웃 난다. 실패가 아니다. 탭 주소가 `accounts.commerce.naver.com/oauth/callback` 으로 바뀌었는지 본다

## 3. 영수증 캡차가 "계속 틀렸다"고 나올 때

가상 영수증 그림을 보여 주고 질문에 답하게 한다(가장 비싼 물건 이름 / 가게 번지 / 전화번호 뒤에서 N번째 숫자 / 어떤 물건을 몇 개 샀나).

**한 번 틀리면 그 모달은 죽는다.** 서버는 틀릴 때마다 새 질문을 발급하는데(`rcaptcha.nid.naver.com/question?...&reload=N`) **화면의 그림과 질문은 바뀌지 않는다.** "새로고침" 버튼을 눌러도 그대로다. 그래서 옛 그림을 보고 넣는 답은 무엇이든 `CaptchaIncorrect` 가 된다. 이걸 모르면 "분명히 맞는 답인데 틀렸다고 나온다"는 상태로 몇십 분을 쓴다.

| 증상 | 판정 | 할 일 |
|---|---|---|
| 틀렸다고 나온 뒤에도 같은 영수증·같은 질문이 보인다 | 모달이 죽었다 | **닫기 → "인증"(또는 "보기")을 다시 눌러 새 모달**을 띄운다. 페이지를 새로 고칠 필요는 없다 |
| 새 모달 | 화면과 서버가 맞는다 | **한 번에 맞힌다.** 틀리면 다시 닫고 연다 |
| 주소가 두 줄로 나뉜 영수증 | 윗줄 "○○길 6" 다음 줄에 "13" 이면 번지는 613 | 줄바꿈을 이어 읽는다 |

자동화 쪽에서 원인을 가릴 때는 추측하지 말고 `Network.enable` 뒤 "확인"을 눌러 요청을 본다. 제출은 `POST /ko/api/v2/developer-accounts/email-verification/request` 에 `{seed, answer, sessionKey}` 이고, 실패 응답은 422 `{"code":"CaptchaIncorrect"}` 다. 모달 안 그림은 `<img>` 의 `src` 가 data URI 라서 그대로 꺼내 저장하면 된다(이 페이지에서는 화면 캡처 `Page.captureScreenshot` 가 멈추는 경우가 있다).

캡차 자체는 사람이 푼다. 에이전트는 모달을 새로 띄우고 그림을 읽어 주는 데까지만 한다.

## 4. 애플리케이션 등록 폼

| 칸 | 넣는 값 | 이유 |
|---|---|---|
| 허용 IP (최대 3개) | 지금 공인 IP(`curl https://api.ipify.org`) · 집 IP 가 오가는 다른 주소 · **고정 IP 서버(VPS) 하나** | 허용 목록에 없는 IP 에서는 **토큰 발급부터 403** 이다. 가정용 회선은 IP 가 바뀐다. IP 가 바뀐 날부터 수집이 며칠씩 비는 경우가 흔하다. VPS 를 하나 넣어 두면 집 IP 가 바뀌어도 그 서버를 프록시로 써서 우회할 수 있다 |
| API 그룹 | 문의 · 상품/N배송 · 정산 · 주문 판매자 · 판매자정보 전부 | 나중에 더하려면 앱을 수정해야 한다. 내 스토어 전용 앱이라 넓게 받아도 위험이 늘지 않는다 |
| 토큰 스펙 확인 체크 | 필수 | 토큰 요청은 `Content-Type: application/x-www-form-urlencoded`, 본문도 폼 형식이고 `grant_type=client_credentials` 를 포함한다. 지키지 않으면 신규 앱은 에러가 난다 |

폼의 "추가" 버튼은 글자가 같은 것이 둘이다. **첫 번째 "추가" = IP 칸 옆, 마지막 "추가" = API 그룹 쪽.** 텍스트로 버튼을 찾을 때 순서를 가려 누른다. "등록" 뒤에는 완료 안내 상자의 "확인"을 한 번 더 누른다.

### 4-1. 403 `GW.IP_NOT_ALLOWED` 가 났을 때

API 센터에서 허용 IP 를 매번 갈아 끼우지 않는다. 코드 쪽에 **"403 IP_NOT_ALLOWED 면 VPS 프록시로 한 번 더"** 폴백을 넣는다.
토큰 발급과 이미지 업로드는 서로 다른 요청 경로라서 **둘 다** 폴백으로 감싸야 한다(하나만 감싸면 토큰은 받는데 이미지 업로드에서 다시 403 이 난다).

## 5. 끝나고 확인

- 앱 상세 주소 = `/ko/member/application/manage/detail;id=<애플리케이션 ID>`
- 토큰 발급을 한 번 해 본다. 403 이면 허용 IP, 에러 본문에 스펙 문구가 있으면 §4 의 토큰 스펙 문제다
- 내 계정 메모에 앱 이름·허용 IP·키 보관 위치를 적어 둔다. 키 값 자체는 적지 않는다
- 앱 인증에는 기한이 있다. 재인증 날짜를 캘린더에 넣어 둔다

## 6. API 로 상품 등록 (`POST /v2/products`)

| 항목 | 통하는 값·방법 |
|---|---|
| 그림 | `POST /v1/product-images/upload`(multipart, 필드 `imageFiles`, 한 번에 10장)로 올린 네이버 주소만 쓴다. 대표 이미지에 외부 주소는 안 된다 |
| 상세 | 스마트스토어는 `<style>` 을 걸러 낸다. 자사몰 상세 HTML 을 860px 폭으로 렌더해 1,800px 단위 JPEG 로 잘라 `<img>` 로 넣고, 검색용으로 문안을 인라인 스타일 `<p>` 로 아래에 붙인다 |
| 배송이 없는 상품(디지털 상품 등) | 배송 정보가 필수라 `deliveryType DIRECT` · `deliveryFee FREE` · 반품·교환 0원으로 넣는다. 그러면 화면에 "무료배송·직접배송"이 뜨므로 **상세 맨 위에 "택배로 오는 상품이 아닙니다" + 실제 전달 방식**을 적는다 |
| 주문자에게 받을 값 | 주문 때 이메일·아이디 같은 값을 받아야 하면 `detailAttribute.optionInfo.optionCustom: [{groupName}]`(직접입력형 옵션)을 넣는다. 없으면 주문이 와도 전달할 곳을 모른다 |
| 그 밖 | `originAreaCode 03`(상세설명 참조) · `productInfoProvidedNoticeType ETC` · A/S 전화는 사업용 번호 |
| 카테고리 | `GET /v1/categories?last=true` 로 말단 카테고리를 받는다. 코드·템플릿 같은 디지털 상품은 디지털/가전 > 소프트웨어 > 유틸리티, 서비스형 상품은 여가/생활편의 > 생활편의 > 온라인 콘텐츠 > 기타 콘텐츠 쪽이 권한 오류 없이 통과한다 |
| 공식 문서 | 일반 웹 가져오기로는 API 센터 문서가 안 읽힌다. 로그인된 브라우저로 받아 둔다. 하위 스키마는 접혀 있어 안 보이므로, 1개를 실제로 등록해 서버 오류 문구로 맞춰 간다(시도 횟수 상한을 먼저 정한다) |
| 판정 | 200 은 등록 요청이 받아들여졌다는 뜻일 뿐이다. `POST /v1/products/search` 로 다시 세고, 구매자 화면을 열어 본다 |

## 7. 브랜드 커넥트·쇼핑 커넥트 (크리에이터 제휴 판매)

스마트스토어 사업자는 누구나 쓸 수 있다. 고정비가 0원이고, 크리에이터 링크로 팔려 구매 확정된 주문에만 판매자가 정한 사용료 + 판매자 마케팅 수수료(작성 시점 0.91%)가 붙는다.

| 순서 | 무엇 | 사람이 해야 하는 것 |
|---|---|---|
| 1 | `brandconnect.naver.com` > 캠페인사 > 시작하기 > 회원가입 3단계(필수 약관만) | 없음 |
| 2 | 스페이스 만들기: 광고주 · 스마트스토어 "사용함" > 연동하기 > 커머스 ID 인증(네이버 재로그인) > 연동 동의 | 없음. 연동하면 사업자 정보·주소가 스토어 등록값으로 채워지고 잠긴다 |
| 3 | 개설하기 > 확인 > 스페이스 이용약관 동의 > 개설 완료 | 없음 |
| 4 | "톡톡 생성 대기 중" > 톡톡 생성 > 휴대폰 인증 | **문자 인증번호**. "발송되었습니다" 안내창이 입력칸을 가리니 먼저 닫는다(5분 제한) |
| 5 | 쇼핑 커넥트 메뉴 진입 | **네이버 아이디 2단계 인증이 켜져 있어야 한다.** 휴대폰 네이버 앱 > 설정 > 내 정보·보안 기능 > 2단계 인증. 켠 뒤 재로그인할 때 휴대폰 승인 1회 + "이 브라우저는 2단계 인증 없이 로그인" 체크 |
| 6 | 쇼핑 커넥트 시작하기 > 솔루션 추가 > 커머스솔루션마켓 '브랜드 커넥트 - 쇼핑 커넥트'(FREE) 추가 > 확인 체크 > 신청 | 없음. **신청 뒤 심사가 있다.** 승인만으로는 상품 관리가 계속 404 다. 판매자센터 커머스솔루션 '사용 중' 목록의 [사용하기] → 브랜드 커넥트 [쇼핑 커넥트 시작하기] → 이용 약관 동의까지 해야 열린다 |
| 7 | 상품 관리 > 진행 상품 등록하기 > 상품 선택 → 사용료 설정 → 유의사항 확인 → 시작하기 | 없음. **사용료는 드롭다운 하나로 선택한 상품 전체에 일괄 적용**된다(상품마다 다르게 하려면 묶음을 나눠 여러 번 등록한다). 선택지는 7~50%, 상한 50%, 부가세 별도 |

**등록하면 다음 달 1일까지 묶인다**(화면 원문 "다음 달 1일 전까지 진행을 취소하거나 변경할 수 없습니다"). 낮추기·중지는 [변경]에 넣어 두면 다음 달 1일 00시부터 적용되고, 올리기만 즉시 된다. 그래서 월말에 가깝게 등록할수록 되돌리기 쉽다.

판정은 화면 글이 아니라 네트워크 응답으로 한다. 등록 요청(`affiliate/command/affiliate-products`)의 응답 `completedCount` 와, 상품 관리를 새로 고칠 때 나가는 `affiliate/query/affiliate-products/search` 응답의 `commissionRate`·`enabled`·`paging.total` 을 내 상품 목록과 대조한다.
