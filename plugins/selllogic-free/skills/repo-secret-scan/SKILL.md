# 저장소 공개 전 비밀 검사

**받는 사람은 지금 파일이 아니라 저장소 전체를 받는다.** 파일에서 지운 키도 커밋 이력에 남아 있으면 `git log -p` 한 줄로 보인다.
그래서 검사는 세 곳을 본다: 지금 파일(파일명 포함) · 커밋 이력에 추가됐던 줄 · 커밋 작성자 이름·메일과 메시지.

## 0. 준비 (처음 한 번)

```bash
python scripts/secret_scan.py --init          # ~/.secret-scan.json 예시를 만든다
```

설정 파일의 `names` 에 **나만 아는 민감 목록**을 정규식으로 넣는다. 비밀키 모양(sk-·xox·AIza·ghp_·EAA·AKIA·개인키 등)과 휴대폰·주민번호 모양은 기본으로 검사하므로 넣지 않아도 된다.

| 항목 | 넣을 것 | 예 |
|---|---|---|
| 고객사명 | 고객사 한글·영문 이름, 쇼핑몰 아이디, 도메인 | `회사A\|companya\|companya\.co\.kr` |
| 내 실명·계정 | 실명, 네이버·구글·깃허브 아이디, 개인 메일 | `홍길동\|myid123` |
| 내부 경로 | 내 PC 사용자 폴더, 사내 폴더 이름 | `C:[\\/]+Users[\\/]+myname` |
| 사업자·계좌 | 사업자번호, 계좌번호 | `123-45-67890` |
| `allow` | 일부러 넣은 예시값(걸리면 안 되는 것) | `010-0000-0000`, `example\.com` |

**설정 파일은 검사할 저장소 안에 두지 않는다.** 민감 목록 자체가 유출 경로가 된다. 스크립트는 설정 파일이 저장소 안에 있으면 경고한다.

## 1. 검사

```bash
python scripts/secret_scan.py <저장소 경로>            # 지금 파일 + 이력 + 작성자·메시지
python scripts/secret_scan.py <경로1> <경로2>           # 여러 저장소 한 번에
python scripts/secret_scan.py <경로> --no-history      # 지금 파일만 (고친 뒤 빠른 재확인)
```

종료 코드는 0 = 0건, 1 = 찾은 것이 있음, 2 = 실행 오류다. 공개·초대 직전 게이트로 쓸 수 있다.

**찾은 값은 앞 4글자까지만 출력한다**(짧은 값은 절반 이상을 가린다). 검사 보고서를 채팅·이슈·슬랙에 붙이는 순간 그 보고서가 새 유출 경로가 되기 때문이다.
AI 에이전트에게 결과를 옮길 때도 가린 출력만 넘긴다.

## 2. 결과 읽기와 조치

| 걸린 곳 | 뜻 | 할 일 |
|---|---|---|
| `[현재]` 비밀키 모양 | 지금 파일에 키가 있다 | **먼저 그 키를 발급처에서 폐기·재발급한다.** 그다음 코드에서 빼고 환경변수·`.env` 로 옮긴다. 이미 한 번이라도 push 했다면 지우는 것만으로는 안전하지 않다 |
| `[현재]` 이름·경로 | 제작 기록(작업 메모·설계 문서·시험 데이터)이 따라 들어갔다 | 받는 사람에게 필요 없는 문서는 `git rm --cached` + `.gitignore`(로컬 파일은 남는다). 시험 문자열은 `shop.example.co.kr` 같은 가짜 값으로 바꾼다 |
| `[이력]` | 지금 파일에는 없고 과거 커밋에만 있다 | 아래 §3 판단 기준 |
| `[메타]` | 커밋 작성자 메일이나 메시지에 들어 있다 | 개인 메일이면 앞으로는 `git config user.email` 을 깃허브 noreply 주소로. 과거 것은 §3 |
| `[추적]` 비밀 모양 파일 | `token.json`·`.env`·`*.db` 같은 파일이 커밋돼 있다 | `git rm --cached <파일>` 후 `.gitignore` 에 추가. 안에 진짜 값이 있었다면 폐기·재발급 |
| `[.gitignore]` 무시되지 않는 표본 | 받는 사람이 자기 키 파일을 실수로 커밋할 수 있다 | `python scripts/secret_scan.py --print-gitignore >> .gitignore` 로 기본 블록을 넣는다 |

고친 뒤에는 **같은 검사를 다시 돌려 0건을 확인**한다. "고쳤다"는 말이 아니라 재검사 출력이 완료 증거다.

## 3. 이력 재작성(filter-repo + 강제 push)을 할지 판단

| 이력에 남은 것 | 판단 |
|---|---|
| 실제 비밀값(키·토큰·비밀번호) | **키를 먼저 폐기·재발급한다.** 폐기하면 이력의 값은 죽은 값이 된다. 아직 아무에게도 준 적 없는 저장소면 이력 재작성까지 한다 |
| 고객의 비공개 자료(주문 내역·개인정보·계약 내용) | 재작성한다. 폐기로 해결되지 않는 정보다 |
| 내부 경로·내 브랜드명·내 계정명·제작 메모 | 대개 **안 해도 된다.** 지금 파일에서 빼는 것으로 충분하다 |
| 이미 남이 복제(clone·fork)한 저장소 | 강제 push 로 **남의 복제본은 회수되지 않는다.** 오히려 받은 사람의 업데이트가 충돌하고 다시 복제해야 한다. 재작성의 이득이 이 비용보다 클 때만 한다 |

공개 전환(private → public)을 앞둔 저장소라면, 이력 재작성 대신 **이력 없이 새 저장소를 만들어 지금 파일만 올리는 것**이 가장 깔끔하다.

## 4. 코드가 스스로 비밀을 흘리는 곳 (정규식으로 안 잡힌다)

스캐너는 **저장된 글자**만 본다. 실행 중에 새는 경로는 코드를 읽어 확인한다. 자주 새는 자리는 셋이다.

1. **외부 API 오류 본문을 그대로 예외·로그·알림에 올리는 곳.** 서버가 요청에 쓴 토큰을 오류 메시지에 되돌려 주는(반사) 경우가 있다. 그 문자열이 로그와 슬랙 알림으로 간다
2. **가림을 한 곳에만 둔 경우.** 요청에 쓰는 인증값이 여럿이면(access token, 앱 시크릿, `앱ID|시크릿` 조각, refresh token) 전부를 가림 대상으로 넘겨야 한다. 하나만 가리면 나머지가 샌다
3. **리다이렉트를 따라가며 인증 헤더를 다른 호스트로 넘기는 요청.** 인증이 붙은 요청은 리다이렉트를 따르지 않게 막는다

그래서 **가림은 두 겹으로 둔다.** ①값을 만드는 자리(예외를 만들 때 그 요청의 인증값을 전부 지운다) ②최종 출력 자리(로그 쓰기·알림 보내기·상태 파일 저장 직전에 한 번 더). 한 겹만 두면 새 코드 경로가 생길 때마다 뚫린다.
확인은 **가짜 토큰을 되돌려 주는 가짜 오류 응답**을 만들어 실제로 태우고, 로그·알림에 그 가짜 토큰이 0번 나오는지 센다.

같은 이유로 발송·갱신처럼 밖으로 나가는 동작은 기본값을 "확인만"으로 두고, 실제 실행은 `--apply` 같은 명시 플래그로만 하게 만든다.

## 5. 공개 직전 체크

| # | 확인 | 판정 |
|---|---|---|
| 1 | `secret_scan.py <경로>` | 합계 0건 (또는 남은 것이 전부 §3 기준으로 "안 해도 된다") |
| 2 | `.gitignore` 기본 블록 | `[.gitignore]` 경고 없음 |
| 3 | `README`·예시 설정 | 예시값이 가짜 값인지(`example.com`, `010-0000-0000`) |
| 4 | 이미지·PDF | 스캐너는 건너뛴다. **캡처 이미지는 열어서 눈으로** 본다(고객 화면·주소창·계정명이 찍히기 쉽다) |
| 5 | 저장소 공개 여부 | 유료로 주는 저장소가 public 으로 열려 있지 않은지 `gh repo view <이름> --json visibility` |
