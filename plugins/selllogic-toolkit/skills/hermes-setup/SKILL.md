# 내 슬랙에 AI 비서 붙이기

헤르메스 = 슬랙에 상주하는 AI 에이전트. 멘션하면 답하고, 크론으로 혼자 일하고, 스킬을 읽어 절차를 따른다.
Claude Code 가 내 터미널에서 일한다면, 헤르메스는 **내가 자는 동안 슬랙에서** 일한다.

## 0. 시작 전에 갖출 것

| 항목 | 비고 |
|---|---|
| 슬랙 워크스페이스 | 내가 관리자인 곳. 앱 설치 권한이 필요하다. **Claude Code Study 워크스페이스는 안 된다** |
| LLM API 키 | 유료. 저렴한 모델로 시작해도 된다 |
| 상주시킬 곳 | 처음엔 내 PC. 24시간 필요해지면 클라우드로 옮긴다 |

## 0-1. 어느 슬랙에 붙일지부터 정한다 (Claude 는 이 절을 건너뛰지 않는다)

**슬랙 앱 생성 화면은 브라우저에 로그인된 워크스페이스를 기본으로 고른다.** 스터디원은 대부분
Claude Code Study 에 로그인해 있어서, 그대로 만들면 고객 슬랙이 아니라 스터디 워크스페이스에 설치된다
(2026-09-22 실제로 발생: 스터디에 "Hermes" 가 하나 더 설치되며 기존 봇과 슬래시 명령 수십 개가 겹쳤고,
관리자에게 명령마다 알림이 한 통씩 갔다).

Claude 는 매니페스트를 만들기 전에 사용자에게 아래 두 가지를 묻고 답을 받는다.

1. **붙일 워크스페이스 주소** (예: `acme-corp.slack.com`). 이 값을 설치 확인 단계(§5)의 `--expect` 로 쓴다
2. **그 워크스페이스가 아직 없거나 내가 관리자가 아니면** 여기서 멈추고 아래 순서를 안내한다

| 상황 | 할 일 |
|---|---|
| 내 연습용 슬랙이 없다 | slack.com/get-started 에서 새 워크스페이스를 만든다(무료). 만든 사람이 관리자다 |
| 고객 슬랙에 붙인다 | 고객에게 **관리자(또는 앱 설치 허용) 권한으로 초대**를 받는다. 초대 수락 후 그 워크스페이스에 로그인됐는지 확인한다 |
| 고객이 권한을 못 준다 | 고객 관리자가 직접 앱을 설치하게 한다(매니페스트 파일을 전달). 토큰 2종만 받는다 |

브라우저 오른쪽 위 워크스페이스 이름이 **붙일 곳**인지 확인한 다음에 §2 로 간다.

## 1. 설치

```bash
hermes --version        # 설치 확인
hermes profile list     # 프로필 목록
```

프로필 = 봇 한 마리. 워크스페이스마다 하나씩 만든다.

## 2. 슬랙 앱 만들기 (여기서 대부분 막힌다)

```bash
hermes slack manifest > manifest.json
```

생성된 매니페스트에서 `slash_commands` 의 `url` 키를 지운다. Socket Mode 에는 필요 없는데,
남아 있으면 앱 생성이 거부된다.

api.slack.com → Your Apps → **From a manifest** → 워크스페이스 선택 → 붙여넣기 → 생성.

**워크스페이스 선택 칸은 기본값을 믿지 않는다.** 목록에서 §0-1 에서 정한 이름을 직접 고른다.
Claude Code Study 가 골라져 있으면 그대로 두지 않는다.

### 실제로 겪는 함정

| 증상 | 원인·해법 |
|---|---|
| Next 버튼이 계속 비활성 | 에러를 찾지 말고 **모달 본문을 끝까지 스크롤**. 워크스페이스 선택기가 매니페스트 에디터 아래 숨어 있다 |
| 빈 앱이 만들어짐 | 에디터에 붙여넣기가 안 먹은 것. **성공 판정 = "Your manifest has Socket Mode enabled" 노란 배너** |
| AI agent 템플릿으로 생성됨 | "From a manifest" 타일을 확실히 선택했는지 확인 |
| 앱 생성 자체가 막힘 | 워크스페이스 **앱 한도 10개**. 안 쓰는 앱을 지우고 모달을 닫았다 다시 연다(한도를 캐시한다) |

토큰 2종을 확보한다.

| 토큰 | 어디서 | 용도 |
|---|---|---|
| `xoxb-...` | OAuth & Permissions | 봇이 말하기 |
| `xapp-1-...` | Basic Information → App-Level Tokens | Socket Mode 연결 |

## 3. 프로필 만들기

```bash
hermes profile create myteam
```

기존 프로필을 복제할 수도 있다.

```bash
hermes profile create myteam --clone-from other
```

> `--clone-from` 과 `--no-skills` 는 **상호 배타**다. 같이 쓰면 실패한다.

### 복제했으면 반드시 기억을 비운다

`memories/MEMORY.md` 를 지운다. **복제 원본의 기억(경로·워크스페이스 ID·토큰 파일 위치)이 통째로 따라와
새 봇 답변에 섞인다.** 외부 인원이 쓰는 봇이면 그대로 정보 유출이다.

프로필 `.env` 에 넣을 것:

| 키 | 값 |
|---|---|
| `SLACK_BOT_TOKEN` | `xoxb-...` |
| `SLACK_APP_TOKEN` | `xapp-1-...` |
| `SLACK_ALLOWED_USERS` | 이 봇을 쓸 사람의 슬랙 ID. **비워두면 워크스페이스 전원이 쓴다** |
| `SLACK_HOME_CHANNEL` | 봇이 기본으로 말할 채널 |

## 4. 인격 만들기 (SOUL.md)

봇이 누구인지, 무엇을 하고 무엇을 하지 않는지 쓴다. 여기에 꼭 넣을 절이 하나 있다.

> **"링크·파일 경로를 받았을 때"**
> 슬랙 프로필은 노션·시트·드라이브 URL 을 열지 못한다. 그런데 봇은 "가져오겠다"고 답한다.
> 규칙 = ① 열었다고 말하지 않는다 ② 링크는 위치 포인터로만 기억한다 ③ 내용은 본문 붙여넣기를 요청한다

이 절이 없으면 봇이 "확인해봤는데요"라고 태연히 지어낸다.

## 5. 기동과 검증

**게이트웨이를 켜기 전에 설치된 워크스페이스를 확인한다.** 통과하지 않으면 켜지 않는다.

```bash
python "<이 스킬 폴더>/scripts/check_workspace.py" --profile myteam --expect acme-corp.slack.com
```

| 결과 | 할 일 |
|---|---|
| `[통과]` | 아래로 진행 |
| `[중단] Claude Code Study 워크스페이스에 설치됐습니다` | api.slack.com/apps → 그 앱 → Install App → Uninstall. 붙일 워크스페이스에 로그인한 브라우저에서 §2 부터 다시. 스터디에 남은 앱은 스터디 관리자에게 삭제를 요청한다 |
| `[중단] 붙이려던 곳은 … 인데` | 위와 같다. 토큰을 다른 워크스페이스 것으로 바꿔 넣지 않았는지도 본다 |

```bash
hermes gateway restart      # .env·설정을 고쳤으면 필수
hermes gateway status
```

**사람 계정으로 실제 멘션을 걸어 왕복을 확인한다.** 봇이 봇을 멘션하는 테스트는 어댑터가 드롭해서
"조용히 성공한 것처럼" 보인다.

채널 초대는 사람이 `/invite @봇이름`. 봇 토큰에는 채널에 스스로 들어가는 권한이 없다.

## 6. 무응답 진단 순서

```bash
hermes gateway status       # 생사
hermes gateway restart      # 대부분 여기서 해결
hermes -z "질문"            # 게이트웨이 없이 1회 질의 (문제 분리)
```

| 증상 | 원인 |
|---|---|
| 갑자기 죽음 | **데스크톱 앱을 켜면 게이트웨이를 밀어낸다**(기동 순간 1회). 켠 뒤 `gateway status` 확인 |
| 카드가 굳음 | `hermes tools disable <도구> --platform slack` + restart. 설정 파일 직접 편집은 안 먹는다 |
| 답이 증발 | 작업 중 말을 걸어 턴이 끊긴 것(로그에 `interrupted_during_api_call`). 새 메시지를 보내면 새 턴 |
| 좀비(프로세스는 살아 있고 소켓만 죽음) | 네트워크 끊김 후 "Socket Mode unhealthy" 반복. 근본 해결은 24시간 도는 서버로 이관 |
| 크론·위임 잡이 HTTP 400 | 하위 모델이 상위 모델의 옵션을 거부한다. `delegation.model`·`cron.model` 을 상위 모델로 + restart |
| 스킬이 안 잡힘 | SKILL.md 의 `platforms` 확인. 스킬은 "쓰라고 알려줄" 필요 없고 description 이 트리거다 |
| 응답이 안 보임 | 답은 **assistant 스레드**로 달린다. 채널 본문만 보면 없는 것처럼 보인다 |

## 7. 절대 규칙

| 규칙 | 이유 |
|---|---|
| 스터디 워크스페이스에 개인·고객 봇을 설치하지 않는다 | 기존 봇과 슬래시 명령이 겹치고, 고객용 봇이 스터디원 전원에게 보인다. `check_workspace.py` 가 막는다 |
| 급여·인사·계좌를 봇 경로에 넣지 않는다 | 필요하면 별도 앱 + 별도 서버로 격리한다 |
| `SLACK_ALLOWED_USERS` 를 비워두지 않는다 | 워크스페이스 전원이 내 봇을 쓰게 된다 |
| 복제 프로필은 기억을 비운다 | 원본의 경로·ID가 답변에 섞여 나간다 |
| 토큰은 `.env` 에만 | 커밋·슬랙 붙여넣기 금지. 유출되면 즉시 재발급 |
| 실멘션으로 검증한다 | 기동 로그가 깨끗해도 왕복이 안 되는 경우가 있다 |
